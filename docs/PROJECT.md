# 🚀 영림-이카운트 통합 자동화 시스템 (V10) 개요

본 문서는 시스템의 기술적 구조, 데이터 흐름 및 핵심 설계 원칙을 요약한 개발 개요서입니다.

---

## 1. 프로젝트 목표 (Project Goal)
- **주문 수집 자동화**: 영림 OMS 사이트에서 수십 건의 주문서를 30분 주기로 자동 수집 및 로컬 저장.
- **ERP 입력 자동화**: 수집된 데이터를 이카운트 ERP가 요구하는 품목 코드 및 규격으로 변환하여 실시간 입력.
- **운영 안정성 확보**: 다중 PC 환경(V10)에서의 중복 처리 방지 및 장애 발생 시 복구 로직 강화.

---

## 2. 기술 스택 (Technical Stack)

| 구분 | 기술 / 라이브러리 | 용도 |

---

## 3. 핵심 아키텍처 (Core Architecture)

### 🛰️ V10 Distributed System
V10의 가장 큰 특징은 **분산 락(Distributed Lock)** 시스템입니다.
- **중복 방지**: 구글 시트를 중앙 저장소로 사용하여, 여러 대의 PC가 동시에 같은 주문을 처리하지 않도록 제어합니다.
- **상태 관리**: 각 주문의 진행 상태(Processing, Completed, Failed)를 실시간으로 공유합니다.

### 🧩 모듈형 설계 (Modular Design)
- **`v10_auto_server.py`**: 전체 프로세스를 총괄하는 메인 엔진 및 웹 서버.
- **`downloader.py`**: 영림 사이트 감시 및 MHTML 파일 수집 스레드.
- **`transformer.py`**: HTML 데이터 파싱 및 ERP 품목 코드 변환 로직.
- **`uploader.py`**: Playwright를 이용한 이카운트 ERP 데이터 주입.

---

## 4. 데이터 흐름 (Data Flow)

1. **감시 (Watch)**: `downloader`가 영림 OMS의 견적/원장 현황을 30분 주기로 모니터링합니다.
2. **락 확인 (Locking)**: 새로운 주문 발견 시, 구글 시트에서 락을 획득합니다. (단일 PC 모드 시 스킵)
3. **추출 (Parsing)**: 수집된 MHTML/HTML 파일의 테이블 데이터를 분석하여 품목명, 규격, 수량을 추출합니다.
4. **변환 (Transform)**: 600개 이상의 유동적인 품목 변환 규칙을 적용하여 ERP용 데이터를 생성합니다.
5. **업로드 (Upload)**: 사용자가 대시보드에서 '업로드' 클릭 시, CDP로 연결된 브라우저의 ERP 창에 데이터를 자동 입력합니다.

---

## 5. 주요 기능 및 성과 (Key Features)

- **CDP 기반 브라우저 제어**: 사용자가 로그인한 원본 브라우저(Edge)에 그대로 접속하여 보안 인증 우회.
- **MHTML 완벽 복원**: 윈도우 인코딩(CP949) 및 Quoted-Printable 형식의 주문서를 완벽하게 파싱.
- **지능형 스케줄러**: 주문 발생 빈도에 따라 확인 주기를 조절하여 서버 부하 및 사이트 차단 방지.
- **장애 복구 시스템**: 예외 발생 시 포트 강제 정리 및 브라우저 재연결 로직을 통한 무중단 운영 지향.
