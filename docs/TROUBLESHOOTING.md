# 🛠️ 프로젝트 트러블슈팅 가이드 (Troubleshooting)

본 문서는 시스템 구축 및 운영 과정에서 발생했던 주요 문제와 그 해결책을 기록합니다. 유사한 문제가 발생할 경우 이 가이드를 참고하십시오.

---

## 1. Edge 브라우저 실행 및 경로 탐색 문제

### 🚩 문제 상황
- 각 PC마다 Microsoft Edge 설치 경로(Program Files vs Program Files (x86))가 달라 브라우저를 찾지 못하는 현상이 발생했습니다.
- 브라우저를 디버그 모드(`--remote-debugging-port=9333`)로 실행하지 않을 경우 자동화 서버가 브라우저를 제어할 수 없었습니다.

### ✅ 해결 방법
- `start_edge_debug.bat` 파일을 개선하여 `EDGE_EXE` 경로를 자동으로 탐색하도록 로직을 추가했습니다.
- **주요 옵션**: 
  - `--remote-debugging-port=9333`: 필수 디버그 포트 설정
  - `--user-data-dir`: 사용자 로그인 세션(영림 사이트) 유지를 위해 실제 사용 중인 프로필 경로를 연동했습니다.

## 2. 좀비 서버 및 포트 충돌 (Port 5080)

### 🚩 문제 상황
- 서버를 재시작할 때 이전 실행 프로세스가 완전히 종료되지 않아 "Address already in use" 에러가 발생하거나, 여러 개의 서버가 동시에 떠서 명령이 꼬이는 현상이 발생했습니다. (사용자가 명명한 '좀비 서버' 문제)

### ✅ 해결 방법
- **자동 정리 로직**: `v10_auto_server.py` 시작 시 5080 포트를 점유 중인 기존 프로세스를 찾아 자동으로 종료(`taskkill`)하는 코드를 삽입했습니다.
- **수동 정리**: 문제가 지속될 경우 `netstat -ano | findstr :5080` 명령으로 PID를 확인한 후 `taskkill /F /PID [번호]`를 사용하여 강제 종료합니다.

## 3. 브라우저 세션 및 "새 기기 승인" 문제

### 🚩 문제 상황
- 별도의 자동화 전용 프로필폴더를 생성하여 사용하려 했으나, 매번 "새로운 기기에서 접속했습니다"라는 승인 요청이 뜨며 자동화 처리가 중단되었습니다.

### ✅ 해결 방법
- **기존 프로필 직접 연동**: 별도의 폴더 대신 사용자가 실제 사용 중인 `Default` 프로필 폴더를 직접 디버그 모드로 열도록 수정하여 로그인 상태를 완벽하게 유지했습니다.

## 4. 분산 락(Distributed Lock) 연결 실패

### 🚩 문제 상황
- Google Sheets와 연동하여 락을 관리하려 했으나, `google_oauth_credentials.json` 파일이 없거나 인증이 만료되어 서버가 시작되지 않는 문제가 있었습니다.

### ✅ 해결 방법
- **Standalone 모드 도입**: 락 서버 연결에 실패하더라도 시스템이 멈추지 않고 단일 PC 모드(Standalone)로 자동 전환되어 정상 동작하도록 예외 처리를 강화했습니다.
- **설정 비활성화**: 단일 PC 운영 시에는 `.env`에서 `ENABLE_DISTRIBUTED_LOCK=false`로 설정하여 불필요한 시도를 제거했습니다.

## 5. 배치 파일 한글 깨짐 및 인코딩

### 🚩 문제 상황
- 배치 파일(`.bat`) 내의 한글 주석이나 메시지가 깨져서 명령어가 올바르게 실행되지 않는 현상이 발생했습니다.

### ✅ 해결 방법
- 모든 배치 파일의 텍스트를 영문 기반으로 수정하거나, ANSI 인코딩으로 저장하여 한글 윈도우 커맨드 창에서의 호환성을 확보했습니다.
