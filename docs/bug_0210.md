# Selenium 자동화 실행 불가 문제 요약 (shop_50)

## 1. 문제 개요

영림 자동화 시스템(shop_50)에서  
브라우저는 실행되지만 **다운로드가 시작되지 않고**,  
`data/youngrim_session.json` 세션 파일이 생성되지 않는 문제가 발생함.

---

## 2. 최초 증상

- `start_all.bat` 실행 시
  - Edge 브라우저는 정상 실행
  - DevTools listening 로그 출력
- 그러나:
  - 다운로드 루프 미시작
  - 세션 파일 미생성
  - `SessionNotCreatedException` 발생

---

## 3. 원인 분석 흐름

### 3.1 세션 관련 진단
- Headless 모드에서는 로그인 세션 생성 불가
- `restart_edge_with_login.bat` 실행 필요
- 그러나 로그인 후에도 `youngrim_session.json` 생성 ❌

➡️ **로그인 문제 아님**

---

### 3.2 Selenium 에러 핵심 로그
SessionNotCreatedException
Failed to establish browser connection


➡️ WebDriver 세션 자체가 생성되지 않음

---

### 3.3 Edge 환경 점검 결과

CMD 기준 확인:

- `msedge --version` ❌
- `where msedge.exe` ❌
- `C:\Program Files\Microsoft\Edge\Application` 경로 ❌
- 존재 파일: `.pma` 등 Store 내부 데이터만 존재

➡️ **결론**
- 해당 PC의 Edge는 **Microsoft Store(AppX) 버전**
- `msedge.exe` 실행 파일 없음
- Selenium에서 **Edge 사용 불가**

---

## 4. 핵심 결론

### 🔴 문제의 본질
- 실행/코드/설정 문제가 아님
- **로컬 PC 브라우저 환경 제약 문제**

### ❌ 불가능한 것
- Store Edge + Selenium
- Edge 기반 세션 생성

### ⭕ 가능한 것
- 설치형(Desktop) 브라우저 + Selenium

---

## 5. 최종 해결 방향 결정

### 선택지 비교

|------|------|------|
| A | Chrome + chromedriver 전환 | ✅ 선택 |

➡️ **선택 A 확정**

## 6. 현재 상태

- Edge: Store(AppX) 버전만 존재
- Chrome: 설치 안 됨
- Selenium 실행 불가 상태

## 7. 다음 단계 (확정)

1. **설치형 Chrome 다운로드 및 설치**
   - Store ❌

6. 자동 다운로드 정상 시작

## 10. 2026-03-24 Windows 작업 스케줄러 실패

### 증상
- 월~토 06:00 자동 시작 스케줄이 등록되어 있으나 서버가 시작되지 않음
- `LastTaskResult: 1` (실패) 확인. 실행은 시도되었으나 즉시 종료됨

### 원인 (3가지)

**1) 실행 경로 오류 (핵심)**
- 등록된 경로: `C:\Users\DSAI\Downloads\files (2)\START.bat`
- 올바른 경로: `C:\Users\DSAI\Desktop\shop_ver20.10_new\START_SCHEDULED.bat`
- `docs\윈도우_작업스케쥴\setup_scheduler.bat`이 Downloads 폴더에서 실행되어 `%~dp0` 경로가 잘못 해석됨
- **파일이 존재하지 않아 exit code 1로 즉시 종료**

**2) `START.bat`의 `pause` 명령**
- 수동 실행용 `START.bat`에는 로그인 확인을 위한 `pause >nul` (라인 31)이 있음
- 스케줄러에서 실행 시 키 입력을 받을 수 없어 영원히 대기 상태

**3) Edge 브라우저 미시작**
- `START_SCHEDULED.bat`이 Edge 디버그 모드를 시작하지 않고 바로 `run_server.py`만 실행
- Edge가 꺼져있으면 브라우저 연결 실패로 서버 종료

### 조치
1. `setup_scheduler.bat` 재실행 → 올바른 절대경로로 재등록
2. `START_SCHEDULED.bat` 보강:
   - 기존 python/Edge 프로세스 정리 (`taskkill`)
   - Edge 디버그 모드 자동 시작 (포트 9333)
   - 10초 대기 후 `run_server.py` 실행
   - 모든 단계 로그 기록 (`logs/scheduler_YYYYMMDD.log`)
3. `STOP_SCHEDULED.bat` 경로도 올바르게 재등록 확인

### 검증
- 스케줄러 XML 확인: `cmd /c "C:\Users\DSAI\Desktop\shop_ver20.10_new\START_SCHEDULED.bat"` 정상 등록
- 다음 자동 실행 예정: 2026-03-25 06:00

### 교훈
- `%~dp0` 기반 상대경로는 실행 위치에 따라 달라지므로, 스케줄러 등록 시 **절대경로** 사용 필수
- 스케줄러용 배치 파일에는 `pause`, 대화형 명령 사용 금지
- 스케줄러 실행 배치에는 의존 프로세스(Edge 등) 시작 로직을 포함해야 함
