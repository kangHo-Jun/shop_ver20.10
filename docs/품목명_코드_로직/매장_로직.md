# 매장 품목명/품목코드 통합 로직

- 기준 파일: `GAS_Source/code_generation.gs`
- 문서 기준일: 2026-05-07
- 이 문서는 기존 `매장_로직.md`와 `이비즈_로직.md` 내용을 현재 코드 기준으로 합쳐 정리한 통합본입니다.

## 1. 한눈에 보는 전체 흐름

- 한 줄 요약: 한 줄 입력 데이터는 `회사명 찾기 → 품목명 만들기 → 품목 분류 → 코드 만들기 → 단위 정하기` 순서로 처리됩니다.

```text
HTML 표 한 줄 읽기
→ 색상 / 품명 / 규격 / 비고 추출
→ 회사명 찾기
→ 품목명용 전처리
→ 품목명 생성
→ 품목 분류
→ 브랜드/색상코드 생성
→ 분류별 중간코드 생성
→ 규격코드 생성
→ 최종 품목코드 조합
→ 단위 생성
→ 결과 시트 / ERP 시트 출력
```

핵심은 아래 두 줄입니다.

- 품목명: 사람이 읽기 쉬운 이름
- 품목코드: ERP가 읽기 쉬운 코드

같은 입력을 써도 결과 모양은 다를 수 있습니다.

예:
- 품목명: `영림174 PVC 프레임몰딩 155바`
- 품목코드: `Y174PP155`

## 2. 입력 데이터는 어떤 모양인가

- 한 줄 요약: 실제로 중요한 입력은 `색상`, `품명`, `규격`, `비고`입니다.

한 줄 데이터는 아래처럼 들어옵니다.

| 위치 | 의미 | 예시 |
|---|---|---|
| `row[2]` | 색상 | `영림174`, `PX444-1 발렌무디 다크` |
| `row[3]` | 품명 | `발포문틀 와이드`, `YA-07MXAL ABS도어`, `프레임몰딩155돌출15(PS,PW)` |
| `row[4]` | 규격 | `140*2230/N`, `900*2100`, `128*/` |
| `row[5]` | 수량 | `2` |
| `row[7]` | 금액 | `150000` |
| `row[8]` | 비고 | `40*9`, `100번`, 빈값 |

초보자는 아래 3개부터 보면 됩니다.

```text
색상(color)
품명(itemName)
규격(spec)
```

## 3. 전체 절차를 단계별로 설명

- 한 줄 요약: 코드는 먼저 회사를 정하고, 그다음 품목명을 만들고, 마지막에 품목코드를 만듭니다.

### 3-1. 회사명 찾기: `detectCompany()`

- 한 줄 요약: 입력이 영림인지 우딘인지 예림인지 먼저 정합니다.

찾는 순서:
1. HTML 전체 내용에서 찾기
2. 색상/품명 텍스트에서 찾기
3. 못 찾으면 기본값 `예림 / y`

현재 매핑:

| 찾는 값 | 표시명 | 브랜드코드 |
|---|---|---|
| `영림` | `영림` | `Y` |
| `www.yl.co.kr` | `영림` | `Y` |
| `우딘` | `우딘` | `W` |
| `예림` | `예림` | `y` |

예:
- 입력 색상: `영림174`
- 결과: 표시명 `영림`, 브랜드코드 `Y`

이 결과는 두 군데에 쓰입니다.
- 품목명 앞에 회사명 접두사 붙일지 판단
- 품목코드 앞 브랜드/색상코드 생성

### 3-2. 품목명용 전처리

- 한 줄 요약: 품목명을 만들기 전에 색상, 품명, 규격을 각각 따로 다듬습니다.

#### A. 색상 전처리: `preprocessColorForProductName()`

색상은 “사람이 읽기 좋게” 정리합니다.

| Before | After | 설명 |
|---|---|---|
| `영림116(PS010)` | `영림116PS010` | 괄호만 제거 |
| `영림116 PS010` | `영림116PS010` | 공백 제거 |
| `영림116 백색` | `영림116` | 숫자 뒤 한글 설명 제거 |
| `PX450-3 발렌무디 다크` | `PX450-3` | 영어+숫자+한글 혼합일 때 한글 제거 |
| `중 백색` | `중백색` | 한글 공백 제거 |

중요:
- 이 규칙은 색상에 적용됩니다.
- 문짝 품명 전체를 여기서 지우는 것은 아닙니다.

#### B. 품명 전처리: `preprocessItemNameForProductName()`

품명에서 너무 긴 설명을 일부 줄입니다.

| Before | After | 설명 |
|---|---|---|
| `40MM평판` | `평40` | `MM평판`을 짧게 바꿈 |
| `40MM평판 문틀 (식기X)` | `평40` | `문틀`, `(식기X)` 제거 |
| `210바 발포문틀` + 규격 `2100*900` | `발포` 쪽으로 정리 | 규격 첫 숫자와 붙은 한글 제거 |

#### C. 규격 전처리: `preprocessSpecForProductName()`

규격은 사람이 보기 좋은 말로 바꿉니다.

| Before | After |
|---|---|
| `140*2230/N` | `140*2230식기무` |
| `900*2100/S` | `900*2100식기유` |
| `900*2100/Y` | `900*2100식기유` |
| `900*2100/A` | `900*2100A` |
| `128*/` | `128*` |

### 3-3. 프레임몰딩 품목명 예외

- 한 줄 요약: 프레임몰딩은 일반 품명 조합을 쓰지 않고, 정해진 표준 형식으로 다시 만듭니다.

프레임몰딩 품목명 형식:

```text
[PVC 또는 MDF] + 프레임몰딩 + [숫자]바
```

규칙:
- `PVC` 또는 `(PS,PW)`가 있으면 `PVC`
- 그 외는 `MDF`
- `프레임몰딩` 뒤 숫자를 뽑아 `155바`처럼 붙임
- 규격은 품목명에서 제거
- 나머지 설명은 버림

예:

| 입력 품명 | 결과 품명 조각 |
|---|---|
| `프레임몰딩155돌출15(PS,PW)` | `PVC 프레임몰딩 155바` |
| `프레임몰딩155돌출15(MDF)` | `MDF 프레임몰딩 155바` |
| `프레임몰딩155돌출15` | `MDF 프레임몰딩 155바` |

### 3-4. 회사명 접두사 붙이기: `shouldAddCompanyPrefix()`

- 한 줄 요약: 색상이나 품명에 회사명이 이미 있으면 앞에 또 붙이지 않습니다.

품목명 기본 구조:

```text
[회사명 접두사(필요할 때만)] + [색상] + [품명] + [규격]
```

예:
- 색상: `영림174` → 이미 회사명 있음 → 접두사 안 붙음
- 색상: `PX444-1 발렌무디 다크` → 회사명 없음 → 기본값 `예림` 붙음

## 4. 품목 분류는 어떻게 하나

- 한 줄 요약: 품목코드를 만들기 전에 이 품목이 문틀인지, 문짝인지, 레일인지, 몰딩인지 먼저 정합니다.

분류 함수: `classifyTarget()`

분류 결과:

| 값 | 의미 |
|---|---|
| `FRAME` | 문틀 계열 |
| `DOOR` | 문짝 계열 |
| `RAIL` | 레일 계열 |
| `MOLDING` | 몰딩 계열 |
| `NONE` | 어느 쪽도 아님 |

우선순위:

1. `FRAME`
2. `RAIL`
3. `DOOR`
4. `MOLDING`
5. `NONE`

### 4-1. 문틀 `FRAME`

키워드:
- `문틀`
- `발포`
- `분리형`
- `스토퍼`
- `목재`
- `슬림형`
- `와이드형`

예:
- `발포문틀 와이드`
- `분리형 문틀`
- `목재 슬림형`

### 4-2. 레일 `RAIL`

조건:
- `레일` 포함
- 문짝 키워드/문짝 패턴은 없어야 함

예:
- `초슬림 상부레일`

### 4-3. 문짝 `DOOR`

조건:
- `문짝`, `ABS`, `도어`, `M/D`, `민무늬`, `탈공`, `미서기`, `미닫이`
- 또는 모델 패턴
- 또는 `숫자+연동`

예:
- `YA-07MXAL ABS도어`
- `YA-100 ABS도어`
- `YS-A12 문짝`
- `3연동 도어`

### 4-4. 몰딩 `MOLDING`

조건:
- `몰딩`, `평`, `코너`, `계단`, `천정`, `천장`, `걸레`, `문선`, `보드`, `루버`, `루바`, `기둥`

예:
- `40MM평판`
- `코너몰딩`
- `프레임몰딩155돌출15(PS,PW)`

### 4-5. 분류 실패 `NONE`

예:
- `부속 손잡이`

이 경우 품목코드는 빈값일 수 있습니다.

## 5. 품목명 생성 규칙

- 한 줄 요약: 품목명은 기본 조합 규칙을 따르되, 프레임몰딩 같은 예외 품목은 별도 규칙을 탑니다.

기본 구조:

```text
[회사명 접두사(필요할 때만)] + [색상 전처리 결과] + [품명 전처리 결과] + [규격 전처리 결과]
```

### 5-1. 문틀 품목명

구조:

```text
[색상] + [정리된 품명] + [정리된 규격]
```

예:
- 입력: `영림116 PS010 / 발포문틀 와이드 / 140*2230/N`
- 결과: `영림116PS010 발포 와이드 140*2230식기무`

### 5-2. 문짝 품목명

문짝 품목명은 대체로 원래 모델명을 유지합니다.

예:
- 입력: `PX444-1 발렌무디 다크 / YA-07MXAL ABS도어 / 900*2100`
- 결과: `예림PX444-1 YA-07MXAL ABS도어 900*2100`

중요:
- 문짝 품목명에서 `YA-07MXAL`을 `YA07`로 바꾸는 것은 아닙니다.
- `YA07`로 줄이는 작업은 품목코드 생성 단계의 `generateModelCode()`에서 일어납니다.

### 5-3. 몰딩 품목명

일반 몰딩은 기본 조합을 따릅니다.

예:
- 입력: `중백색 / 40MM평판 / (40*9)`
- 결과: `예림중백색 평40 (40*9)`

### 5-4. 프레임몰딩 품목명

프레임몰딩은 별도 형식:

```text
[색상] + [PVC 또는 MDF] + 프레임몰딩 + [숫자]바
```

예:
- `영림174 / 프레임몰딩155돌출15(PS,PW) / 128*/`
  → `영림174 PVC 프레임몰딩 155바`
- `영림174 / 프레임몰딩155돌출15 / 128*/`
  → `영림174 MDF 프레임몰딩 155바`

## 6. 품목코드 생성 규칙

- 한 줄 요약: 품목코드는 `브랜드/색상코드 + 분류별 중간코드 + 규격코드` 구조로 만듭니다.

기본 구조:

```text
[브랜드/색상코드] + [중간코드] + [규격코드]
```

### 6-1. 브랜드/색상코드: `generateBrandColorCode()`

대표 예:

| 입력 색상 | 브랜드 | 결과 |
|---|---|---|
| `영림116` | `Y` | `Y116` |
| `PS140` | `y` | `yS140` |
| `PX444-1` | `y` | `yX4441` |
| `중백색` | `y` | `y중백` |

### 6-2. 문틀 코드: `generateFlagCode()`

상위코드:

| 조건 | 코드 |
|---|---|
| `발포` | `B` |
| `목재` | `W` |
| `방염` | `F` |
| `비방염` | `N` |
| `알루미늄` | `A` |

하위코드:

| 조건 | 코드 |
|---|---|
| `슬림와이드` | `I` |
| `와이드` | `W` |
| `슬림` | `S` |
| `차음` | `E` |
| `일반형` | `G` |
| `가변형` | `K` |
| `분리형`, `스토퍼` | `D` |
| `일체` | `B` |
| `히든` | `H` |
| `스텝` | `T` |
| `무메`, `무매` | `M` |
| `미서기`, `미닫이` | `L` |

현재 대표 결과:

| 입력 품명 | 중간코드 |
|---|---|
| `발포문틀 와이드` | `BW` |
| `발포문틀 슬림` | `BS` |
| `목재` | `W` |
| `목재 슬림형` | `WS` |
| `목재 와이드형` | `WW` |

### 6-3. 문짝 코드: `generateModelCode()`

가장 중요한 규칙:

- 문짝 품명에 `영어 + (-) + 숫자 + 영어` 형식이 있으면
  - 숫자 뒤 영어 전체 삭제
  - 하이픈 삭제

예:

| Before | After |
|---|---|
| `YA-07MXAL` | `YA07` |
| `YA-07E` | `YA07` |
| `TA-04E` | `TA04` |

또한:
- `YA-100` → `YA100`
- `YS-A12` → `YSA12`
- `탈공 도어` → `탈`
- `M/D 민무늬` → `MD`

처리 순서:

1. `영어-숫자+영어` 확인
2. 맞으면 숫자 뒤 영어 삭제 + 하이픈 삭제
3. 아니면 `영어-영어+숫자` 확인
4. 아니면 `탈공`, `M/D 민무늬`, `OO도어` 순서 확인

### 6-4. 레일 코드: `generateRailCode()`

예:

| 입력 품명 | 결과 |
|---|---|
| `초슬림 3연동 레일` | `SS3레일` |
| `슬림 상부레일` | `S상레일` |
| `하부레일` | `하레일` |

### 6-5. 몰딩 코드: `generateMoldingFlagCode()`

대표 규칙:
- `천장` 포함 → `천장`
- `프레임몰딩 + PVC 또는 (PS,PW)` → `PP`
- `프레임몰딩 + 그 외` → `PM`
- `기둥` 포함 → `기둥`
- 일반 몰딩은 `몰딩`, `받이`, `평판`, 괄호 등을 지우고 남은 말 사용

프레임몰딩 대표 결과:

| 입력 품명 | 중간코드 |
|---|---|
| `프레임몰딩155돌출15(PS,PW)` | `PP` |
| `프레임몰딩155돌출15(MDF)` | `PM` |
| `프레임몰딩155돌출15` | `PM` |

### 6-6. 규격코드

#### 일반 품목: `generateSpecCode()`

규격 안 숫자를 이어 붙이고, 마지막 슬래시 문자도 붙입니다.

예:

| 입력 규격 | 결과 |
|---|---|
| `140*2230/N` | `1402230N` |
| `900*2100` | `9002100` |
| `150*2300/S` | `1502300S` |

#### 몰딩 전용: `generateMoldingSpecCode()`

몰딩은 일반 규격코드를 쓰지 않고 별도 규칙을 탑니다.

대표 규칙:
- 프레임몰딩: `프레임` 뒤 숫자 우선
- 기둥: `(숫자*숫자*숫자)` 패턴
- 평판: `(40*9)` 또는 `40MM평판`
- 비고 안 숫자 패턴도 참고

예:

| 입력 품명/규격 | 규격코드 |
|---|---|
| `프레임몰딩155돌출15(PS,PW)` / `128*/` | `155` |
| `40MM평판` / `(40*9)` | `40` |
| `코너몰딩` / `(30*30)` | `3030` |

### 6-7. 최종 코드 조합

최종 구조:

```text
[브랜드/색상코드] + [중간코드] + [규격코드]
```

예:

| 입력 | 최종 코드 |
|---|---|
| `영림116 PS010 / 발포문틀 와이드 / 140*2230/N` | `Y116BW1402230N` |

## 7. 단위 규칙

- 한 줄 요약: 단위는 분류를 기준으로 정하고, 일부 몰딩/레일만 예외가 있습니다.

| 분류 | 기본 단위 | 예외 |
|---|---|---|
| `FRAME` | `틀` | 특정 특수 규격은 `개` |
| `DOOR` | `짝` | 없음 |
| `RAIL` | `개` | 없음 |
| `MOLDING` | `EA` | `템바보드 → 롤`, `템바루바 → BOX` |
| `NONE` | 빈값 | 코드도 빈값일 수 있음 |

프레임몰딩은 현재 `MOLDING`이라서 `EA`입니다.

## 9. 새로운 품목이 추가될 때 보는 순서

- 한 줄 요약: 새 품목은 항상 `분류 → 품목명 예외 → 중간코드 → 규격코드 → 단위` 순서로 검토하면 됩니다.

체크리스트:

1. 이 품목은 어느 분류인가?
   - `FRAME / DOOR / RAIL / MOLDING / NONE`
   - 먼저 `classifyTarget()`을 봅니다.

2. 품목명 예외가 필요한가?
   - 일반 조합으로 충분한가?
   - 프레임몰딩처럼 표준 형식으로 다시 써야 하나?

3. 중간코드는 어느 함수에서 만들까?
   - 문틀: `generateFlagCode()`
   - 문짝: `generateModelCode()`
   - 레일: `generateRailCode()`
   - 몰딩: `generateMoldingFlagCode()`

4. 규격은 일반 규칙으로 충분한가?
   - 일반이면 `generateSpecCode()`
   - 몰딩처럼 예외가 많으면 `generateMoldingSpecCode()`

5. 단위는 무엇으로 나와야 하나?
   - `틀 / 짝 / 개 / EA / 롤 / BOX`

6. 회사명 없는 입력도 생각했는가?
   - 기본값이 `예림 / y`라는 점을 꼭 확인

7. 실제 예시 2~3개로 결과를 확인했는가?
   - 품목명
   - 품목코드
   - 단위

## 11. 마지막 정리

- 입력의 핵심은 `색상 + 품명 + 규격`
- 품목명은 사람 읽기용, 품목코드는 ERP용
- 먼저 분류를 정해야 뒤 규칙이 결정됨
- 문짝 모델명, 목재, 프레임몰딩은 현재 중요한 예외 품목
- 새 품목이 들어오면 아래 5가지만 보면 빠르게 설계 가능

```text
분류
→ 품목명 예외 여부
→ 중간코드 생성 함수
→ 규격코드 생성 함수
→ 단위
```
