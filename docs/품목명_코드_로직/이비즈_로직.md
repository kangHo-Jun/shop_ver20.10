# 이비즈 품목명/품목코드 로직

- 기준 파일: `GAS_Source/code_generation.gs`
- 문서 기준일: 2026-05-07
- 대상 독자: 코딩 초보자

## 1. 전체 흐름

이 스크립트는 업로드된 HTML/MHTML 견적 파일에서 표 데이터를 읽어서, 사람이 보기 쉬운 `품목명`과 ERP 업로드용 `품목코드`를 만듭니다.

흐름은 아래 순서입니다.

1. 데이터 입력
   - HTML 표에서 `색상`, `품명`, `규격`, `수량`, `금액`, `비고`를 읽습니다.
2. 회사명 판단
   - HTML 내용이나 데이터 안에 `영림`, `우딘`, `예림` 같은 회사명이 있는지 보고 브랜드를 정합니다.
3. 품목명 생성
   - 색상/품명/규격을 각각 정리한 뒤 하나의 문장처럼 합칩니다.
4. 품목 분류
   - 품명이 `문틀`, `문짝`, `레일`, `몰딩` 중 어디에 해당하는지 판단합니다.
5. 품목코드 생성
   - `브랜드/색상코드 + 분류별 코드 + 규격코드`를 붙여 최종 코드를 만듭니다.
6. 출력
   - 결과 시트에는 `품목명`, `품목코드`, `단위`를 저장합니다.
   - ERP 시트에는 날짜, 수량, 금액, 비고까지 함께 저장합니다.

간단한 그림으로 보면 아래와 같습니다.

```text
원본 데이터
→ 회사명 찾기
→ 품목명용 전처리
→ 품목명 생성
→ 품목 분류
→ 코드 조각 만들기
→ 하이픈 제거
→ 품목코드/단위 출력
```

## 2. 주요 함수 설명

### `detectCompany(allData, htmlContent)`

- 한 줄 요약: 전체 데이터에서 회사명과 브랜드코드를 먼저 정하는 함수입니다.

상세 설명:
- HTML 전체 내용에 `영림`, `우딘`, `예림`, `www.yl.co.kr`가 있는지 먼저 찾습니다.
- 못 찾으면 표 데이터의 색상/품명에서 다시 찾습니다.
- 끝까지 못 찾으면 기본값으로 `예림`, 브랜드코드 `y`를 사용합니다.

입력 예시:

```text
htmlContent = "... www.yl.co.kr ..."
```

출력 예시:

```text
{ display: "영림", brand: "Y" }
```

### `shouldAddCompanyPrefix(color, itemName, companyDisplay)`

- 한 줄 요약: 품목명 앞에 회사명을 붙여야 하는지 판단하는 함수입니다.

상세 설명:
- 색상이나 품명 안에 이미 `영림`, `예림` 같은 회사명이 들어 있으면 또 붙이지 않습니다.
- 다른 회사명이 이미 들어 있어도 붙이지 않습니다.
- 아무 회사명도 없을 때만 앞에 회사명을 붙입니다.

입력 예시:

```text
color = "PX444-1"
itemName = "YA-100 ABS도어"
companyDisplay = "예림"
```

출력 예시:

```text
true
```

### `preprocessColorForProductName(color)`

- 한 줄 요약: 품목명에 들어갈 색상 문자열을 보기 좋게 정리하는 함수입니다.

상세 설명:
- `영림116(PS010)` 형태는 괄호만 없애고 `영림116PS010`으로 만듭니다.
- `영림116 PS010` 형태는 공백을 없애고 붙입니다.
- `영림116 백색`처럼 뒤에 한글 설명이 붙으면 `영림116`만 남깁니다.
- 영어+숫자+한글이 섞여 있으면 한글을 지웁니다.
- 회사명만 붙은 일반 문자열은 `영림`, `우딘`, `예림` 같은 회사 키워드를 제거합니다.
- 한글만 있으면 공백을 없애고 그대로 둡니다.

입력/출력 예시:

| 입력 | 출력 |
|---|---|
| `영림116(PS010)` | `영림116PS010` |
| `영림116 PS010` | `영림116PS010` |
| `영림116 백색` | `영림116` |
| `PX450-3 발렌무디 다크` | `PX450-3` |
| `중 백색` | `중백색` |

### `preprocessItemNameForProductName(itemName, spec)`

- 한 줄 요약: 품목명에 들어갈 품명을 짧고 읽기 쉽게 정리하는 함수입니다.

상세 설명:
- `40MM평판`은 `평40`으로 바꿉니다.
- `문틀`은 지웁니다.
- `(식기X)`, `(식기O)`는 지웁니다.
- 규격의 첫 숫자와 붙어 있는 한글도 지웁니다.
  - 예: 규격이 `2100*900`이면 품명 안의 `210바` 같은 표현을 제거합니다.

입력 예시:

```text
itemName = "40MM평판 문틀 (식기X)"
spec = "2100*900"
```

출력 예시:

```text
"평40"
```

### `preprocessSpecForProductName(spec)`

- 한 줄 요약: 품목명에 넣을 규격 문자열을 사람이 읽기 쉽게 바꾸는 함수입니다.

상세 설명:
- 끝이 `/ N`이면 `식기무`로 바꿉니다.
- 끝이 `/ S` 또는 `/ Y`이면 `식기유`로 바꿉니다.
- 끝이 `/ A` 같은 한 글자면 슬래시(`/`)만 떼고 `A`만 남깁니다.
- 슬래시만 있으면 슬래시를 지웁니다.

입력/출력 예시:

| 입력 | 출력 |
|---|---|
| `140*2230/N` | `140*2230식기무` |
| `900*2100/S` | `900*2100식기유` |
| `900*2100/A` | `900*2100A` |
| `900*2100/` | `900*2100` |

### `classifyTarget(itemName)`

- 한 줄 요약: 품명을 보고 문틀/문짝/레일/몰딩 중 하나로 분류하는 함수입니다.

상세 설명:
- 이 함수는 코드 생성의 출발점입니다.
- 여러 키워드가 동시에 보여도 정해진 우선순위대로 하나만 선택합니다.
- 우선순위는 `문틀 > 레일 > 문짝 > 몰딩`입니다.

입력 예시:

```text
"발포문틀 와이드"
```

출력 예시:

```text
"FRAME"
```

## 3. 품목 분류 기준

### 3-1. 문틀 `FRAME`

- 한 줄 요약: `문틀`, `발포`, `분리형`, `스토퍼`, `목재`, `슬림형`, `와이드형`이 있으면 문틀로 봅니다.

상세 설명:
- `목재`도 문틀 쪽으로 분류됩니다.
- 그래서 목재 예시는 코드상 별도 타입이 아니라 `FRAME`으로 처리됩니다.

예시:

| 품명 | 분류 |
|---|---|
| `발포문틀 와이드` | `FRAME` |
| `목재 슬림형` | `FRAME` |

### 3-2. 레일 `RAIL`

- 한 줄 요약: `레일`이 있고, 문짝 키워드가 없으면 레일로 봅니다.

상세 설명:
- `레일`이라는 글자가 있어도 문짝 패턴이 같이 있으면 레일이 아니라 문짝으로 갈 수 있습니다.
- 다만 현재 우선순위상 문틀 키워드가 있으면 먼저 문틀이 됩니다.

예시:

| 품명 | 분류 |
|---|---|
| `초슬림 상부레일` | `RAIL` |

### 3-3. 문짝 `DOOR`

- 한 줄 요약: `문짝`, `ABS`, `도어`, `M/D`, `민무늬`, `탈공`, `미서기`, `미닫이` 또는 모델 패턴이 있으면 문짝입니다.

상세 설명:
- `YA-100`, `YS-A12` 같은 영문 모델명 패턴도 문짝으로 봅니다.
- `3연동`처럼 `숫자+연동` 패턴도 문짝으로 봅니다.

예시:

| 품명 | 분류 |
|---|---|
| `YA-100 ABS도어` | `DOOR` |
| `3연동 도어` | `DOOR` |

### 3-4. 몰딩 `MOLDING`

- 한 줄 요약: `몰딩`, `평`, `코너`, `계단`, `천정`, `천장`, `걸레`, `문선`, `보드`, `루버`, `루바`, `기둥`이 있으면 몰딩입니다.

상세 설명:
- `평` 한 글자만 있어도 몰딩으로 분류될 수 있습니다.
- `프레임몰딩`, `기둥`, `템바보드`, `템바루바`도 이 그룹에서 처리합니다.

예시:

| 품명 | 분류 |
|---|---|
| `40MM평판` | `MOLDING` |
| `프레임몰딩 MDF 프레임 100번` | `MOLDING` |

## 4. 품목명 생성 로직

품목명은 아래 순서로 만들어집니다.

```text
회사명 접두사(필요할 때만)
+ 색상 전처리 결과
+ 품명 전처리 결과
+ 규격 전처리 결과
```

실제 조합식은 아래와 같은 형태입니다.

```text
${companyPrefix}${colorProcessed} ${itemNameProcessed} ${specProcessed}
```

### 품목명 생성 예시 1

입력:

```text
회사명: 예림
색상: PX444-1 발렌무디 다크
품명: YA-100 ABS도어
규격: 900*2100
```

처리:

```text
색상 → PX444-1
품명 → YA-100 ABS도어
규격 → 900*2100
회사명 접두사 필요 → 예
```

출력:

```text
예림PX444-1 YA-100 ABS도어 900*2100
```

### 품목명 생성 예시 2

입력:

```text
회사명: 영림
색상: 영림116(PS010)
품명: 발포문틀 와이드
규격: 140*2230/N
```

처리:

```text
색상 → 영림116PS010
품명 → 발포 와이드
규격 → 140*2230식기무
회사명 접두사 필요 → 아니오
```

출력:

```text
영림116PS010 발포 와이드 140*2230식기무
```

## 5. 코드 생성 로직

코드는 기본적으로 아래 3조각을 붙여서 만듭니다.

```text
브랜드/색상코드 + 분류별 코드 + 규격코드
```

### `generateProductCode(color, itemName, spec, remarks, brandCode)`

- 한 줄 요약: 품목 분류 후 각 조각 코드를 만들어 최종 품목코드로 합치는 함수입니다.

상세 설명:
1. `classifyTarget`으로 분류합니다.
2. 몰딩이 아니면 규격 숫자가 너무 작은지 검사합니다.
   - 규격 안의 가장 큰 숫자가 `999` 이하면 코드 생성을 중단합니다.
3. `generateBrandColorCode`로 브랜드/색상코드를 만듭니다.
4. 분류에 따라 아래 함수 중 하나를 사용합니다.
   - 문틀: `generateFlagCode`
   - 문짝: `generateModelCode`
   - 레일: `generateRailCode`
   - 몰딩: `generateMoldingFlagCode`
5. 규격코드를 만듭니다.
   - 문틀/문짝/레일: `generateSpecCode`
   - 몰딩: `generateMoldingSpecCode`
6. 마지막에 하이픈(`-`)을 모두 제거합니다.

입력 예시:

```text
color = "PX444-1 발렌무디 다크"
itemName = "YA-100 ABS도어"
spec = "900*2100"
remarks = ""
brandCode = "y"
```

출력 예시:

```text
yX4441YA1009002100
```

### `generateBrandColorCode(color, brandCode)`

- 한 줄 요약: 브랜드 한 글자와 색상 정보를 합쳐 앞부분 코드를 만드는 함수입니다.

상세 설명:
- 회사명 키워드를 먼저 지웁니다.
- 한글이 섞인 `PX450-3 발렌무디 다크` 같은 값은 한글을 먼저 지웁니다.
- 대표 규칙은 아래와 같습니다.

| 입력 색상 | 브랜드 | 출력 |
|---|---|---|
| `PS140` | `Y` | `YS140` |
| `PX444-1` | `y` | `yX4441` |
| `영림116` | `Y` | `Y116` |
| `중백색` | `y` | `y중백` |

### `generateFlagCode(itemName)`

- 한 줄 요약: 문틀용 중간 코드를 만드는 함수입니다.

상세 설명:
- 상위코드:
  - `발포 → B`
  - `방염 → F`
  - `비방염 → N`
  - `알루미늄 → A`
- 하위코드:
  - `슬림와이드 → I`
  - `와이드 → W`
  - `슬림 → S`
  - `차음 → E`
  - `일반형 → G`
  - `가변형 → K`
  - `분리형`, `스토퍼 → D`
  - `일체 → B`
  - `히든 → H`
  - `스텝 → T`
  - `무메`, `무매 → M`
  - `미서기`, `미닫이 → L`
- 하위코드만 있고 상위코드가 없으면 기본 상위코드로 `N`을 씁니다.
- `방염`, `비방염`, `알루미늄`에 `3연동` 같은 표현이 있으면 하위코드 대신 `숫자+C`를 씁니다.

입력/출력 예시:

| 입력 품명 | 출력 |
|---|---|
| `발포문틀 와이드` | `BW` |
| `목재 슬림형` | `NS` |
| `비방염 3연동` | `N3C` |

### `generateModelCode(itemName)`

- 한 줄 요약: 문짝용 모델 코드를 뽑는 함수입니다.

상세 설명:
- `YA-100` 같은 패턴이 있으면 하이픈을 빼고 `YA100`으로 만듭니다.
- 뒤에 한글이 붙으면 한글 앞까지만 씁니다.
- `탈공`이 있으면 `탈`
- `M/D`와 `민무늬`가 같이 있으면 `MD`
- `OO도어` 형태면 `도어` 앞 글자를 사용합니다.

입력/출력 예시:

| 입력 품명 | 출력 |
|---|---|
| `YA-100 ABS도어` | `YA100` |
| `탈공 도어` | `탈` |
| `M/D 민무늬` | `MD` |

### `generateRailCode(itemName)`

- 한 줄 요약: 레일용 중간 코드를 만드는 함수입니다.

상세 설명:
- `3연동`이 있으면 `3레일`처럼 연동 숫자를 넣습니다.
- `초슬림`이면 `SS`, `슬림`이면 `S`를 앞에 붙입니다.
- `상부`, `하부`도 같이 붙입니다.

입력/출력 예시:

| 입력 품명 | 출력 |
|---|---|
| `초슬림 3연동 레일` | `SS3레일` |
| `슬림 상부레일` | `S상레일` |

### `generateMoldingFlagCode(itemName)`

- 한 줄 요약: 몰딩용 중간 코드를 만드는 함수입니다.

상세 설명:
- `천장`이 있으면 바로 `천장`
- `프레임몰딩` 또는 `프레임`이 있으면 `프레임`
- `기둥`이 있으면 `기둥`
- `템바보드`, `템바루바`는 방염 여부와 모양을 따로 조합합니다.
  - 예: `방염 소반달 템바보드` → `F소반달TB`
- 일반 몰딩은 아래처럼 다듬습니다.
  - `몰딩`, `받이` 제거
  - `평판`은 `평`으로 축약
  - `60MM` 같은 두께 숫자 제거
  - 괄호 제거
  - 맨 앞 숫자 제거

입력/출력 예시:

| 입력 품명 | 출력 |
|---|---|
| `40MM평판` | `평` |
| `프레임몰딩 MDF 프레임 100번` | `프레임` |
| `방염 소반달 템바보드` | `F소반달TB` |

### `generateSpecCode(spec)`

- 한 줄 요약: 일반 품목의 규격에서 숫자와 마지막 문자 표시를 뽑아내는 함수입니다.

상세 설명:
- 규격 안의 모든 숫자를 차례대로 붙입니다.
- `/N`, `/S`, `/Y`, `/A`처럼 슬래시 뒤에 문자가 있으면 그 문자도 맨 뒤에 붙입니다.

입력/출력 예시:

| 입력 규격 | 출력 |
|---|---|
| `140*2230/N` | `1402230N` |
| `900*2100` | `9002100` |
| `100*2000/A` | `1002000A` |

### `generateMoldingSpecCode(itemName, spec, remarks)`

- 한 줄 요약: 몰딩 전용 규격코드를 여러 우선순위로 찾는 함수입니다.

상세 설명:
- 프레임몰딩이면 `프레임` 뒤 숫자를 우선 사용합니다.
- 기둥이면 `(숫자*숫자*숫자)` 패턴을 찾습니다.
  - 마지막 숫자가 `9`이면 그 숫자는 버립니다.
- 그다음 순서로 아래를 검사합니다.
  - 규격 칸의 `(40*9)` 같은 패턴
  - 품명 안 괄호 패턴
  - 비고의 `40*9` 패턴
  - 품명의 `(9T)`와 `40MM` 조합
  - 비고의 `9T`와 품명의 `40MM` 조합
  - 템바보드/템바루바의 `숫자*숫자`
  - `100바용`, `100번`
  - `40MM평판`
  - 규격 칸의 단순 숫자

입력/출력 예시:

| 입력 | 출력 |
|---|---|
| 품명:`40MM평판`, 규격:`(40*9)` | `40` |
| 품명:`프레임몰딩 MDF 프레임 100번`, 규격:`100` | `100` |
| 품명:`기둥몰딩`, 규격:`(30*30*9)` | `3030` |

## 6. 하이픈 제거 로직

하이픈 제거는 두 군데에서 일어납니다.

### 6-1. 브랜드/색상코드 단계

- `generateBrandColorCode`에서 `PS140-1`, `PX444-1` 같은 값의 하이픈을 먼저 제거합니다.

예시:

| 입력 | 중간 결과 |
|---|---|
| `PX444-1` | `yX4441` |

### 6-2. 최종 코드 조합 단계

- `generateProductCode` 마지막 줄에서 일반 하이픈(`-`)뿐 아니라 긴 하이픈(`–`, `—`)도 모두 지웁니다.

실제 코드 개념:

```text
(브랜드/색상코드 + 분류코드 + 규격코드).replace(/[-–—]/g, '')
```

의미:
- 중간 단계 어디선가 하이픈이 남아 있어도 최종 결과에서는 제거됩니다.
- 그래서 ERP 코드에는 하이픈이 남지 않습니다.

## 7. 단위 생성 로직

### `generateUnit(itemName, spec, remarks)`

- 한 줄 요약: 품목 분류와 규격 모양을 보고 단위를 정하는 함수입니다.

상세 설명:
- 숫자가 아예 없으면 단위를 비워 둡니다.
- 레일이면 `개`
- 문틀이면 기본 `틀`
  - 단, 규격이 `100*` 또는 `100*200*`처럼 끝나는 특수 형태면 `개`
- 문짝이면 `짝`
- 몰딩이면 기본 `EA`
  - `템바보드`는 `롤`
  - `템바루바`는 `BOX`

입력/출력 예시:

| 입력 품명 | 규격 | 출력 |
|---|---|---|
| `발포문틀 와이드` | `140*2230/N` | `틀` |
| `YA-100 ABS도어` | `900*2100` | `짝` |
| `초슬림 상부레일` | `3000` | `개` |
| `40MM평판` | `(40*9)` | `EA` |

## 9. 주의할 점

초보자 기준으로 특히 헷갈리기 쉬운 부분만 정리하면 아래와 같습니다.

1. 품목명과 품목코드는 같은 원본 데이터를 쓰지만, 전처리 방식이 완전히 같지는 않습니다.
2. `목재`는 별도 분류가 아니라 문틀로 처리됩니다.
3. 몰딩은 일반 규격코드가 아니라 `generateMoldingSpecCode`라는 별도 규칙을 탑니다.
4. 규격이 너무 작은 품목은 코드가 비어 있을 수 있습니다.
5. 최종 코드에서는 하이픈이 제거됩니다.
